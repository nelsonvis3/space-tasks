## Traducción y compatibilidad

El traductor usa WASM en CPU y modelos específicos de traducción, separado del asistente WebGPU. El original permanece disponible y el idioma del documento es independiente del de la interfaz. Se advierte sobre cifras o referencias que no coinciden y sobre una verificación de idioma incierta.

Las pruebas de lógica usan un adaptador simulado de inferencia para verificar límites, reintentos y cancelación; **no prueban calidad de traducción real**. Además se ejecutó `test:translation:real` para descargar los modelos, traducir ejemplos en los siete idiomas y revisar cifras, negación y el concepto de descanso. `test:ocr:real` construyó un PDF de imagen original y comprobó OCR real seguido de traducción al español en Chromium, Firefox y Brave. Ambos recorridos adjuntan salidas para revisión y no simulan los motores.

## Tamaños y optimización

El JavaScript inicial del build vigente pesa aproximadamente 390 kB; la variante Brotli servida por Node pesa 121.558 bytes. El build genera compresión de los recursos públicos de texto y mantiene las respuestas privadas sin comprimir. Se sirve tipografía local y se difieren lector, asistente y personalización. Estas cifras son tamaños de archivos medidos, no FPS, memoria máxima, latencia ni Core Web Vitals de un equipo Intel real.

## Límites antes de distribuir

- El código propio usa GPL-3.0-only. Los PDF proporcionados y sus textos derivados quedaron excluidos, según la actualización al final de este documento. El logo todavía requiere acreditar permiso de redistribución o reemplazarse. No se borraron ni relicenciaron esos originales.
- No se generó un instalador AppImage/Flatpak ni se publicaron binarios para Linux. Android/iPhone quedaron fuera del alcance por decisión del usuario.
- WebKit no pudo arrancar en CachyOS por bibliotecas ausentes; es opcional con `SPACE_TEST_WEBKIT=1`. No se informa compatibilidad Safari comprobada.
- La inferencia del asistente WebGPU y el rendimiento físico en Intel/16 GB no se midieron. La reproducción de audio se ejercitó en el navegador, pero la escucha humana de continuidad/volumen queda pendiente.
- No hay recuperación de contraseña por correo ni purga definitiva de la papelera PDF. Los datos locales y los backups SQLite no están cifrados por esta aplicación.
- Si se elige alojamiento compartido: comprobar HTTPS, cookies, volumen persistente, recuperación de base/PDF y copias fuera del disco. El límite de intentos usa la IP directa; un proxy necesita una configuración revisada para no agrupar a todos los usuarios. No hubo despliegue.

No se garantiza pérdida imposible de datos ni ausencia absoluta de fallos. Sí se comprobaron migraciones, sincronización con desconexión/cuota, aislamiento de cuentas, papelera y restauración de backups con datos sintéticos reales.

## Exclusión posterior de libros del paquete

Por solicitud del usuario, los tres PDF proporcionados y sus tres conversiones se trasladaron a `.local-books/`, fuera de `public/`. Sus hashes SHA-256 coinciden antes y después. El catálogo distribuible quedó vacío y no se indexa automáticamente al iniciar/compilar. Los PDF privados de las cuentas y del navegador no se modificaron.

El build comprueba `public/` y `dist/` y rechaza libros, textos derivados conocidos, copias comprimidas y enlaces simbólicos. `.gitignore` y `.npmignore` excluyen las copias locales y las rutas públicas anteriores. Un archivo sintético bajo `.local-books/` dio HTTP 403 en Vite por ruta directa y `/@fs/`.

Se ejecutó de nuevo `npm run runtime -- run verify`: **76 pruebas aprobadas**, tipos, 465 claves en siete idiomas y build correctos. También pasaron **14 recorridos Chromium/Firefox/ventana estrecha y seis Brave**. La biblioteca empieza vacía; las rutas antiguas devuelven 404 y se sigue importando, leyendo dos páginas y restaurando una muestra PDF original de prueba. El dry run del paquete fuente no incluye libros ni datos privados; su único PDF es esa muestra propia de pruebas. No se repitieron las inferencias, cuyos motores y modelos no cambiaron.
